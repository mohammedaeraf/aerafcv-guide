# **Aeraf CV – Resume Writer Training Programme**

## **Day 13 – Writing Projects, Certifications & Additional Training Sections**

**Module:** Week 2 – Resume Sections\
**Duration:** 10–15 minutes

### **🎯 Learning Objectives**

By the end of this lesson, you should be able to:

- Present academic, personal and professional projects effectively.
- Write project descriptions using clear, action-oriented bullet points.
- Distinguish between certifications, short courses and workshops.
- Decide which projects and training details are relevant to a target job.
- Avoid exaggerating project contributions or claiming qualifications that candidates do not possess.

### **1. Why Are Projects Important in a Resume?**

Projects demonstrate how a candidate has applied their knowledge in practical situations.

They are particularly useful for:

- Freshers who have limited or no employment experience.
- Students and recent graduates.
- Career changers who want to demonstrate relevant skills.
- Professionals who have completed significant technical or work-related projects.

For example, Aisha Rahman is a BCA graduate applying for Junior Web Developer positions. Although she has no formal employment experience, her Campus Events Portal project demonstrates practical frontend development skills.

A well-written project entry can help recruiters understand what the candidate has actually built or contributed to.

### **2. How to Write a Project Entry**

Use this simple structure:

**Project Name**\
Project Type | Year (if available)

- Briefly explain the purpose of the project.
- Describe the candidate's actual contribution.
- Mention relevant tools and technologies.
- Highlight important features or outcomes, where supported.

**Example – Aisha Rahman's Campus Events Portal**

**Campus Events Portal**\
Academic Project

- Developed a responsive event-listing interface using React.
- Implemented category filtering to help users browse events.
- Created event detail views using sample data.
- Applied frontend development concepts to build an interactive user interface.

This example highlights her actual contribution without claiming that the portal was commercially deployed or used by a university.

### **3. What Information Should We Collect About a Project?**

Before writing a project description, ask the candidate:

1. What was the project called?
2. What problem was the project intended to solve?
3. Was it an academic, personal, freelance or professional project?
4. What was your individual contribution?
5. Which programming languages, tools or technologies did you use?
6. What features did you implement?
7. Was the project completed or is it still in progress?
8. Is there a live demonstration, GitHub repository or portfolio link?

**Important:** If a project was completed by a team, distinguish the candidate's individual contribution from the team's overall work.

Do not claim that a candidate independently developed an entire application when they only contributed to one module.

### **4. How to Present Certifications and Training**

Certifications and additional training can strengthen a resume by demonstrating professional development and specialised knowledge.

However, it is important to distinguish between different types of learning.

| Type                          | Description                                                                         | Example                           |
| ----------------------------- | ----------------------------------------------------------------------------------- | --------------------------------- |
| Professional Certification    | A credential awarded after meeting defined assessment or certification requirements | AWS Certified Solutions Architect |
| Course Completion Certificate | Confirmation that a candidate completed a training programme                        | HR Fundamentals Course            |
| Workshop                      | Short introductory or practical training                                            | Introductory React Workshop       |
| Academic Qualification        | Formal education from a recognised educational institution                          | BCA, BA, B.Com                    |

Do not describe a workshop attendee as a certified professional unless they actually earned the relevant certification.

### **5. Recommended Certification Format**

Use this structure:

**Certification / Course Name**\
Issuing Organisation | Completion Year

Where relevant, include:

- Credential ID.
- Verification link.
- Expiry date.
- Relevant specialisation.

Only include these details when available and appropriate.

**Example:**

**HR Fundamentals – Short Course**\
2025 | Completion Certificate

This is suitable for Priya Nair based on the information in our workbook.

The issuing organisation is not provided, so we should ask Priya for that information before finalising the entry.

### **7. Where Should These Sections Appear?**

The placement depends on the candidate's profile.

| Candidate Type           | Suggested Priority                                                               |
| ------------------------ | -------------------------------------------------------------------------------- |
| Fresher                  | Education → Skills → Projects → Training                                         |
| Experienced Professional | Work Experience → Skills → Education → Certifications                            |
| Career Changer           | Professional Summary → Transferable Skills → Work Experience → Relevant Training |
| Technical Professional   | Work Experience → Technical Skills → Projects → Certifications                   |

These are suggested arrangements, not fixed rules. Always prioritise the information most relevant to the target job.

### **8. Common Mistakes to Avoid**

1. Listing a project without explaining what the candidate actually did.
2. Claiming individual ownership of a team project.
3. Adding technologies that the candidate did not use.
4. Presenting a workshop as a professional certification.
5. Including outdated or irrelevant courses.
6. Inventing project results, user counts or business impact.
7. Adding fake GitHub repositories or portfolio links.
8. Listing every online course regardless of relevance.

**Aeraf CV Ethical Rule:** A resume should accurately represent the candidate's education, skills, experience and contributions. Never invent projects, credentials or achievements.

### **9. Short Exercise – Improve a Weak Project Description**

Consider this entry:

**My Website Project**

- Made a website.
- Used HTML and CSS.
- It was very good.
- Everyone liked it.

Identify at least four problems.

Now rewrite it using this hypothetical information:

- Project: Restaurant Menu Website.
- Type: Academic project.
- Tools: HTML and CSS.
- Contribution: Created a responsive menu page with food categories and item descriptions.

Do not add features or results that are not provided.

### **Key Takeaways**

- Projects demonstrate practical application of knowledge.
- Describe the candidate's actual contribution.
- Mention relevant tools, technologies and project features.
- Distinguish certifications from workshops and short courses.
- Include only relevant additional training.
- Use project and training sections strategically based on the candidate's experience.
- Never exaggerate achievements or credentials.
